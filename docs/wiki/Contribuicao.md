# Contribuição

1. Escolha uma issue e crie branch a partir da `main` atualizada.
2. Use nome de branch curto, sem espaços ou acentos, e commits Conventional Commits em português.
3. Mantenha um objetivo por pull request e descreva a validação e os riscos.
4. Rode as verificações pertinentes; para mudança de aplicação, use `npm run verify`.
5. Abra PR para a branch correta, use o template do repositório e solicite revisão.
6. Resolva comentários e aguarde todos os checks obrigatórios. Não faça push direto nas branches
   protegidas nem use bypass para evitar revisão.

Nunca adicione credenciais, dumps, dados pessoais reais ou conteúdo provisório marcado como final.
Mudanças de banco precisam de migration, RLS e plano de rollback. Mudanças de segurança,
autorização, dados pessoais, publicação e integrações precisam de revisão cuidadosa.

O guia normativo completo é
[`CONTRIBUTING.md`](https://github.com/NucleoTechFecap/landing-agencia-benjamin/blob/main/CONTRIBUTING.md).
